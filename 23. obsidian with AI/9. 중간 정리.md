## 현재 목표 구조

```
Mac
 │

 ▼

 ▼

 │

```

현재 **Open WebUI 0.11.3**에는 Native MCP (네이티브 엠씨피, 자체 MCP 연결) 메뉴가 없으므로 당장은 **mcpo** (엠씨피오, MCP-to-OpenAPI 변환 브리지)를 중간에 둡니다.

```
현재
Open WebUI 0.11.3
       │
       ▼
mcpo :8002
       │
       ▼
mcp-obsidian :8001
       │
       ▼
00_newbee Vault
```

향후 Open WebUI 0.12+에서 Native MCP가 안정적으로 사용 가능해지면:

```
향후
Open WebUI 0.12+
       │
       │ Native MCP / Streamable HTTP
       ▼
mcp-obsidian :8001
       │
       ▼
00_newbee Vault
```

따라서 **mcpo만 제거하면 되는 구조**입니다.

---

# 1\. MCP 서버

**MCP** (엠씨피, Model Context Protocol / 모델 컨텍스트 프로토콜)는 `/opt/mcp-obsidian`에 설치합니다.

Node.js는 현재 사용 중인 **v24.15.0**을 그대로 사용합니다.

패키지는 버전을 고정합니다.

```
@modelcontextprotocol/sdk 1.17.3
express                    4.21.2
cors                       2.8.5
```

즉:

```
{
  "type": "module",
  "dependencies": {
    "@modelcontextprotocol/sdk": "1.17.3",
    "express": "4.21.2",
    "cors": "2.8.5"
  }
}
```

이렇게 하면 나중에 `npm install`을 다시 해도 예상치 못한 최신 버전으로 올라가지 않습니다.

---

# 2\. SDK는 v1.17.3으로 유지

현재는 **`@modelcontextprotocol/sdk` 1.17.3**을 사용합니다.

중요한 것은 지금 당장 v2로 넘어가지 않는 것입니다.

```
현재
@modelcontextprotocol/sdk
        │
        └── v1.17.3 고정

향후
Open WebUI 0.12+ 및 MCP v2 지원 상황 확인
        │
        └── 그때 v2 전환 검토
```

즉 **지금은 안정적인 v1 라인을 유지**합니다.

---

# 3\. 전송 방식

MCP 서버는 **Streamable HTTP** (스트리머블 에이치티티피, 스트리밍 가능한 HTTP 전송 방식)를 사용합니다.

주소는:

```
http://localhost:8001/mcp
```

입니다.

그리고:

```
sessionIdGenerator: undefined
```

를 사용하여 **stateless** (스테이트리스, 세션 상태를 서버에 유지하지 않는 방식)로 구성합니다.

구조는:

```
POST /mcp
      │
      ▼
StreamableHTTPServerTransport
      │
      ▼
MCP Server
```

입니다.

# 4\. 현재 MCP 도구

처음에는 4개를 구현해 둡니다.

```
search
read
list
write
```

의미는:

| 도구 | 기능 |
| --- | --- |
| `search` | Markdown 파일 내용 검색 |
| `read` | Markdown 파일 읽기 |
| `list` | 폴더/파일 목록 |
| `write` | Markdown 파일 쓰기 |

다만 **실제 테스트에서는 write를 사용하지 않는 것**이 좋습니다.

먼저:

```
search
read
list
```

만 검증합니다.

---

# 5\. Vault

MCP 서버가 접근하는 실제 Vault는:

```
/mnt/build-data/oci-vaults/00_newbee
```

입니다.

현재 Git 동기화도 완료되어 있고 약 729 MB입니다.

중요한 점은 \*\*Open WebUI의 직접 접근은 계속 `:ro` (read-only, 읽기 전용)\*\*로 유지한다는 것입니다.

MCP 서버가 나중에 쓰기를 담당하게 됩니다.

즉 역할을 분리합니다.

```
Open WebUI
   │
   └── Vault 직접 접근 :ro

MCP
   │
   └── Vault 접근
       ├── read
       ├── search
       ├── list
       └── 나중에 write
```

# 6\. systemd로 MCP 서버 실행

**systemd** (시스템디, Linux 서비스 관리자) 서비스:

```
mcp-obsidian.service
```

포트:

```
8001
```

주소:

```
http://localhost:8001/mcp
```

입니다.

따라서 서버가 재부팅되어도 자동으로 올라오게 합니다.

```
OCI-build 재부팅
      ↓
systemd
      ↓
mcp-obsidian.service
      ↓
:8001/mcp
```

# 7\. 첫 번째 확인

MCP 서버를 설치한 뒤 가장 먼저 이것만 확인합니다.

```
curl -s http://localhost:8001/health | python3 -m json.tool
```

정상이면 대략:

```
{
    "ok": true,
    "vault": "/mnt/build-data/oci-vaults/00_newbee",
    "endpoint": "/mcp",
    "sdk": "1.17.3",
    "protocol": "2026-07-28",
    "mode": "streamable-http-stateless-2026-07-28",
    "tools": 4
}
```

형태가 됩니다.

**여기까지가 1차 목표입니다.**

# 8\. 그 다음 mcpo

MCP 서버가 정상 확인된 다음에 **mcpo**를 설치합니다.

```
mcp-obsidian :8001
       │
       ▼
     mcpo
       │
       ▼
OpenAPI :8002
```

즉 mcpo는 MCP 서버 자체가 아닙니다.

단순히:

```
MCP
 ↓
OpenAPI
```

로 변환해 주는 **임시 호환 계층**입니다.

Open WebUI 0.11.3에서는 이 계층이 필요하고, Native MCP가 가능해지면 제거합니다.

---

# 9\. Open WebUI 0.11.3 연결

mcpo가 정상 작동하면:

```
http://host.docker.internal:8002
```

를 Open WebUI에서 연결합니다.

현재 Open WebUI 컨테이너에는 이미:

```
extra_hosts:
  - "host.docker.internal:host-gateway"
```

가 있으므로 Docker 컨테이너에서 OCI-build 호스트를 접근하기 위한 준비도 되어 있습니다.

최종적으로 Open WebUI에서:

```
search
read
list
write
```

가 Tool로 나타나는지를 확인합니다.
