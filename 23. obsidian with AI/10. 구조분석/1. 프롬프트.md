옵시디언 볼트를 안전하게 분석하고 작업 결과를 새로운 폴더에 마크다운 파일로 누적하는 **'분할 정복 및 아카이빙' 프롬프트 전략**입니다.

AI에게 바로 복사해서 사용할 수 있는 단계별 명령어(Prompt) 구성입니다.

### 1단계: 분석용 아카이브 폴더 생성 지시

먼저 결과물을 저장할 전용 폴더를 만들도록 지시합니다.

Plaintext

```
내 옵시디언 볼트 안에 'AI_Summaries'라는 이름의 새로운 폴더를 생성해 줘. 앞으로 수행하는 모든 분석 및 요약 결과물은 이 폴더 안에 마크다운(.md) 파일로 저장할 거야.
```

### 2단계: 폴더 단위 구조 분석 및 파일 저장 지시

전체 볼트 대신 특정 폴더를 지정해 분석하고, 결과를 파일로 기록하게 합니다.

Plaintext

```
[특정 폴더명, 예: SmartHome] 폴더 안의 파일 목록과 각 파일의 핵심 주제를 분석해 줘. 분석이 끝나면 그 내용을 'AI_Summaries/[폴더명]_분석요약.md' 파일로 생성(저장)해 줘.
```

### 3단계: 요약본 기반 다음 작업 이어가기

이전 대화 맥락이 끊기거나 새로 창을 열었을 때, 기존 요약 파일을 읽게 하여 토큰을 아끼고 맥락을 유지합니다.

Plaintext

```
'AI_Summaries/[폴더명]_분석요약.md' 파일을 읽어와. 이 내용을 바탕으로 다음 세부 작업을 진행해 줘: [원하는 추가 작업 내용 입력]
```


단순한 로그가 아니라 **"Agent 작업 노트"**로 만드는 것입니다.

```
_AI_Analysis/
│
├── README.md
│
├── 00_State/
│   ├── vault-map.md
│   ├── current-state.md
│   └── pending-tasks.md
│
├── 01_Analysis/
│   ├── folders/
│   ├── topics/
│   └── relationships/
│
├── 02_Candidates/
│   ├── move.md
│   ├── rename.md
│   └── merge.md
│
├── 03_Decisions/
│   └── decisions.md
│

```

여기서 역할을 나누는 겁니다.

### `00_State`

**현재까지 Agent가 알고 있는 것**

### `01_Analysis`

**Agent가 조사해서 발견한 것**

### `02_Candidates`

**Agent가 제안하는 것**

### `03_Decisions`

**사용자가 승인/거부한 것**

### `99_Logs`

**실제로 무엇을 했는지**

이렇게 하면 굉장히 강력해집니다.

## 특히 `Decisions`가 중요합니다

예를 들어 Agent가:

```
A.md → Projects/A.md로 이동 제안
```

했고 사용자가:

> 승인

했다면:

```
03_Decisions/decisions.md

2026-08-03
- A.md → Projects/A.md
- 승인
- 이유: 프로젝트 관련 노트
```

가 기록됩니다.

반대로:

> 이건 이동하지 마. 현재 위치가 맞아.

라고 하면:

```
2026-08-03
- A.md
- 이동하지 않음
- 현재 위치 유지
```

라고 기록합니다.

그러면 **Agent가 다음에 같은 판단을 반복하지 않을 수 있습니다.**

이게 사실상 **Agent에게 사용자의 판단 기준을 학습시키는 것**과 비슷한 효과를 냅니다.

# 결과적으로 이런 구조가 됩니다

```
                   Agent
                     │
                     ▼
                  MCP
                     │
        ┌────────────┴────────────┐
        ▼                         ▼
   실제 Vault                 AI Memory
                              _AI_Analysis
                                  │
                ┌─────────────────┼──────────────┐
                ▼                 ▼              ▼
             분석 기록        결정 기록       작업 로그
                │                 │              │
                └─────────────────┴──────────────┘
                                  │
                                  ▼
                            다음 Agent 작업
```

이 구조의 장점은 **무료 AI의 짧은 컨텍스트를 장기적으로 보완할 수 있다는 것**입니다.

그리고 사용자님의 경우에는 이 방식이 특히 좋습니다. 이미 **Obsidian 자체가 지식 관리 시스템**이기 때문에, 별도의 DB나 Vector DB를 처음부터 만들 필요도 없습니다.

### 단, 한 가지 원칙은 지키는 게 좋습니다.

**AI가 분석 기록을 무한정 쌓게 하지 마세요.**

처음에는 로그가 많아져도 괜찮지만, 장기적으로는 Agent에게:

> 작업 후 중요한 발견만 `current-state.md`에 요약하고, 상세 과정은 날짜별 로그에 남겨라.

라고 하면 됩니다.

그러면

```
99_Logs
   ↓
중요한 내용 추출
   ↓
00_State/current-state.md
```

라는 **기억 압축 과정**이 생깁니다.

이것까지 구축하면 나중에는 Agent에게 단순히

> "지난번에 분석했던 Obsidian 구조를 이어서 작업해."

라고 해도 `_AI_Analysis`를 먼저 읽고 **이전 작업 지점부터 이어서 진행하는 Agent**로 발전시킬 수 있습니다.

저라면 지금 단계에서 **`_AI_Analysis` 폴더부터 만들고, 첫 Agent 작업은 "Vault 구조 분석 + 분석 결과를 `_AI_Analysis`에 기록"까지만** 시키겠습니다.
